# Страница книжного клуба с регистрацией — дизайн

Дата: 2026-09-09. Статус: одобрено в чате.

## Цель

Страница `/bookclub/` на xenitch.ru, где человек регистрируется на встречу
Органического книжного клуба: оставляет имя, телефон, почту и формат участия,
после чего попадает на страницу оплаты ЮKassa. Данные регистрации попадают
в гугл-таблицу челленджа «Органические медиа», оплаты сверяются по почте.
Без бэкенда.

## Архитектура

Три части, две из них — в разных репозиториях:

1. **Сайт** (`site/`, git → GitHub Pages). Страница контента + новый шаблон
   с формой и небольшим встроенным скриптом. Первая страница сайта с JavaScript.
2. **Скрипт таблицы** (`tg-collector/club.gs`, четвёртый файл того же Apps Script
   проекта, что и сборщики). Веб-приложение с `doPost`: принимает JSON,
   дописывает строку в лист «Книжный клуб» (создаёт лист с шапкой, если его нет).
3. **ЮKassa** — единая ссылка `https://yookassa.ru/my/i/aqE8U3v4u5ve/l`,
   на неё уводим после успешной записи. В настройках ссылки почта должна быть
   обязательным полем (сверка оплат по почте) — делает владелица руками.

## Поток данных

Браузер → `fetch(POST, Content-Type: text/plain, body = JSON)` на URL веб-приложения
→ `doPost` парсит, валидирует, `appendRow` → отвечает JSON `{ok:true}`
(ContentService, Apps Script сам ставит CORS-заголовки для простых запросов)
→ браузер при `ok` делает `location.href = ссылка ЮKassa`.

Почему `text/plain`: запрос остаётся «простым», без preflight, который
Apps Script не поддерживает. Ответ читать можно, значит ошибку записи видно.

## Страница `/bookclub/`

Файл `content/bookclub/index.md`, frontmatter: `title: Органический книжный клуб`,
`description`, `template: bookclub.html`, `pay_url`, `form_url` (адрес веб-приложения;
до деплоя — пусто, скрипт на странице тогда сразу уводит на оплату, но не пишет в таблицу —
такого состояния на боевом сайте быть не должно).

Содержание (текст владелицы, без правок):

- кикер: Органический книжный клуб
- h1: Ничегонеделание делает нас живыми
- абзац: Обсуждаем книгу «Займись ничем» Джозефа Джебелли и связанные с ней произведения
- два события: 28 сентября 17:30 (кем), оффлайн, Кемерово · 29 сентября, 13:30 (мск), онлайн, Zoom
- стоимость: 500 р.
- форма «Регистрация»: имя, номер телефона, эл. почта, формат участия
  (радио: «Оффлайн, Кемерово, 28 сентября» / «Онлайн, Zoom, 29 сентября»),
  кнопка «Зарегистрироваться».

Текстовая часть — markdown в контенте; форма — в шаблоне `bookclub.html`
(наследует `base.html`). Согласие на обработку данных добавляется завтра
отдельной задачей.

## Шаблон и стиль

`templates/bookclub.html`: `<article class="prose">` с контентом, затем
`<form class="reg-form">`. Стиль в `style.css`: поля — бумага/чернила, нижняя
линейка золотом, лейблы малыми прописными; кнопка — зелёная заливка, при
наведении бордо; без скруглений и теней. Сообщение об ошибке — бордо,
содержит ссылку на оплату («Не удалось записать заявку. Напишите @xenitch
или перейдите к оплате»).

Скрипт на странице (inline в шаблоне, ~30 строк): блокирует кнопку на время
отправки, отправляет JSON, при `ok` — редирект, иначе показывает ошибку.
Поля обязательны через атрибуты `required`, `type=email`, `type=tel`.
Скрытое поле-ловушка `website` для ботов: если заполнено — скрипт таблицы
отвечает ok, но строку не пишет.

## Скрипт таблицы `club.gs`

- `CLUB_CONFIG = { SHEET: 'Книжный клуб' }`, шапка:
  `Дата | Имя | Телефон | Почта | Формат | Оплачено`. Колонку «Оплачено»
  владелица заполняет руками после сверки.
- Чистая функция `parseRegistration(bodyText) → {ok, row?|error}`:
  парсит JSON, обрезает пробелы, проверяет непустые имя/телефон/почту,
  почту по простому регэкспу, формат из двух допустимых значений, ловушку.
  Тестируется локально через jsc (`club-test.js`, стиль `challenge-test.js`).
- `doPost(e)`: `parseRegistration(e.postData.contents)`, при ok —
  `appendRow([new Date(), ...])` с блокировкой `LockService`, ответ
  `ContentService` с JSON. При ошибке — `{ok:false, error}`.
- `doGet` — ответ `{ok:true, service:'bookclub'}` для проверки, что деплой жив.

Деплой (руками владелицы, по инструкции в шапке файла): Развернуть →
Новое развёртывание → Веб-приложение, «От моего имени», доступ «Все».
Полученный URL вписывается в `form_url` страницы.

## Навигация и главная

- `base.html`: пункт «Книжный клуб» в шапке рядом с «Исследование», подсветка
  `current` по `page.url.startswith('/bookclub/')`.
- `content/index.md`: новый абзац со ссылкой на `/bookclub/` — про то, что
  первая живая встреча уже назначена: книжный клуб, 28–29 сентября.

## Тесты

- `tests/test_build.py`: страница с `template:` из frontmatter рендерится этим
  шаблоном (уже покрыто существующим тестом на research.html), плюс проверка,
  что `/bookclub/` собирается и содержит `<form`.
- `tg-collector/club-test.js`: `parseRegistration` — валидная заявка, пропуски
  полей, кривая почта, неизвестный формат, ловушка, не-JSON.
- Живая проверка после деплоя: `curl -X POST` на веб-приложение → строка в листе,
  потом строку удалить.
